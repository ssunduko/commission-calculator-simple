# JUnit Dynamic Tests for Commission Model Classes

## Overview

This directory contains comprehensive JUnit 5 dynamic tests for the commission system model classes. Dynamic tests provide a powerful way to generate tests at runtime, enabling data-driven testing, parameterized scenarios, and flexible test generation based on various conditions.

## What Are Dynamic Tests?

Dynamic tests are a JUnit 5 feature that allows test cases to be created and executed at runtime rather than compile time. Unlike traditional static tests, dynamic tests are generated by factory methods annotated with `@TestFactory`.

### Key Benefits:
- **Data-driven testing**: Generate tests from datasets, CSV files, or external sources
- **Flexible test generation**: Create tests based on runtime conditions
- **Reduced code duplication**: Single test logic applied to multiple scenarios
- **Better test organization**: Group related test scenarios logically

## Test Classes Created

### 1. JUnitDynamicTest.java
**Primary dynamic test class covering core model functionality**

**Key Features:**
- **Deal Validation Tests**: Tests deal creation, product management, and status updates
- **User Role Tests**: Validates user role assignments and role-based functionality
- **Commission Calculation Tests**: Tests base commissions, bonuses, and accelerators
- **Product Calculation Tests**: Validates pricing calculations with various scenarios
- **Enum Validation Tests**: Tests enum values and display names

**Dynamic Test Concepts Demonstrated:**
```java
@TestFactory
Stream<DynamicTest> dealValidationTests() {
    // Test scenarios defined as data
    List<TestScenario<Deal>> scenarios = Arrays.asList(
        new TestScenario<>("Valid Deal Creation", 
            () -> new Deal("Software License", new BigDecimal("10000"), "REP001"),
            deal -> {
                assertNotNull(deal.getTitle());
                assertEquals("Software License", deal.getTitle());
            })
    );
    
    // Generate dynamic tests from scenarios
    return scenarios.stream()
        .map(scenario -> DynamicTest.dynamicTest(
            scenario.name,
            () -> scenario.validator.accept(scenario.supplier.get())
        ));
}
```

## Dynamic Test Patterns Used

### 1. Stream-Based Test Generation
```java
return testData.stream()
    .map(data -> DynamicTest.dynamicTest(
        data.getName(),
        () -> data.getValidator().accept(data.getObject())
    ));
```

### 2. Combinatorial Testing
```java
return IntStream.range(1, 1 << allRoles.length)
    .mapToObj(i -> generateRoleCombination(i))
    .map(combo -> DynamicTest.dynamicTest(
        "Role Combination: " + combo.toString(),
        () -> testRoleCombination(combo)
    ));
```

### 3. Range-Based Testing
```java
int[] quantities = {1, 5, 10, 25, 50, 100};
String[] prices = {"0.99", "9.99", "99.99"};

return Arrays.stream(quantities)
    .flatMap(quantity -> Arrays.stream(prices)
        .map(price -> createPricingTest(quantity, price))
    );
```

## Key Concepts Explained

### @TestFactory Annotation
- Marks methods that generate dynamic tests
- Must return Stream<DynamicTest>, Collection<DynamicTest>, or Iterable<DynamicTest>
- Tests are discovered and executed at runtime

### DynamicTest.dynamicTest()
- Creates individual test instances with display name and executable
- Display names appear in test reports and IDE test runners
- Executables contain the actual test logic

### Test Data Organization
- **TestScenario<T>**: Generic holder for test name, object supplier, and validator
- **ValidationTestCase**: Specific structure for validation scenarios
- **CommissionTestCase**: Domain-specific test case structure

### Stream-Based Generation
- Leverages Java 8 Streams for efficient test creation
- Enables functional programming patterns in test generation
- Supports complex data transformations and filtering
